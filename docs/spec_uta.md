## 1. 何を作るか

耳の遠い人が、歌の形（音の高さ・長さ・大きさ・歌詞）を目で受け取る画面を作る。

- **画面を見るのは聴く人**（耳の遠い人）。画面には触らない。
- **操作するのはそばの人**。曲名を押す、画面に触って止める、だけで使える。
- **線は楽譜から描く**。伴奏の混ざった音から高さを読まないので、安い機種でも線が出る。
- **鳴らすのは、伴奏と Gin の歌声を一緒に**。伴奏は、元の伴奏附の楽譜（権利の切れた本）から起こしたもの。

### 使う場面の全体像（Gin、2026-11-03）
- 元の伴奏に合わせて、Gin が主旋律を歌います。録るときは伴奏をヘッドホンで聞き、声だけを録ります。
- アプリは、伴奏と Gin の歌声を一緒に流し、線は楽譜から描きます。
- 使う人は Chrome でページを開き、耳の遠くなった人に音を見てもらいます。
- 環境が許せば、画面ミラーリング・MHL・Miracast などでテレビに映し、レクなどで楽しんでもらいます。
- 文字と線は、離れて見ても読める大きさにします。横向きの大きな画面でも崩れないようにします。

### カラオケとの違い
カラオケは、歌う人が正しく歌うためのもの。音めがねは、聴く人が歌の形を受け取るためのもの。そのため、次のことを守る。

- 採点も、ずれの表示も出さない。
- 線は、太さの変わる一本の線にする（お手本の線と自分の声の線を並べない）。
- 線の太さの言い方（Gin、2026-11-05）：見る人に向けた所（README の使い方・画面に出す見方・デモ）は「太さは音の大きさ。大きく歌う所ほど太い」で統一する。仕組みの説明の所だけ、出どころを書き分ける：いまは楽譜の強弱記号（p・mp・mf・f）から。歌声が入る T6 からは声の大きさから。
- 歌詞の字を、色で塗り替えていく見せ方（ワイプ）はしない。

### 作らないもの
- 会話や声かけの見せ方（README の A〜D）。
- 話す人向けの「声モード」。
- 聞こえを測る機能。
- 録音の機能。歌声は、アプリの外で Gin が録る（6 章）。
- 医療の判断や、効き目を思わせる言葉。

## 3. 置き方と画面

### 置き方
- スマホは横向きにして、机に立てます。
- 環境が許せば、テレビに映します（画面ミラーリング・MHL・Miracast など）。音もテレビから出ます。
- 文字と線は、テレビから離れて見ても読める大きさにします。大きさは画面の大きさに合わせて変え、横向きの大きな画面でも崩れないようにします。

### 画面の割り当て（横向き）

```
┌──────────────────────────────────────────────┐
│ ▁▂▃▅▆▅▃▁ ▁▂▃▅▇▆▃▁ ▁▂▃▅▆▃▁   ← 地図（細い帯）       │
│        ▲                                         │
│              │                                   │
│   ━━━━━━━━━━━│━━━━  ┄┄┄┄┄┄  ┄┄┄┄┄             │ ← 線
│   過ぎた所    │いま     この先（暗め）             │
│                                                  │
│   うさぎ追（お）いし　かの山（やま）  ← いまの行   │
│   小鮒（こぶな）釣りし　かの川       ← 次の行     │
└──────────────────────────────────────────────┘
```

#### 線
- 横は時間で、右から左へ流れます。
- 「いま」の縦線は、左から 1/3 の所に止めておきます。
- 右側の 2/3 には、これから歌う所の線を暗めに出します。
- 縦は音の高さです。曲ごとの音域（いちばん低い音〜いちばん高い音に、上下 2 半音ずつ足した幅）で、画面いっぱいに使います。（Claude の案）
- 太さは、録った声の大きさです。声のファイルは前もって全部読むので、これから歌う所にも太さが付きます。
- 休みの所（休符）は、線を切ります。
- 一度に見える長さは約 8 秒です。父の反応を見て直す候補にします。（Claude の案）
- 高さの目盛り（横線・音名）は出しません。（Claude の案）

#### 歌詞
- 線の下に置きます。
- いまの行を大きく、ルビ付きで出します。
- 次の行は、それより小さく、暗めに出します。
- 行が替わるときは、次の行がいまの行の場所へ上がるだけにします。明るさを急に変えません。

#### 地図
- 画面のいちばん上に置く、細い帯です。
- 曲全体の声の大きさを山の形で描き、いまの位置に印を付けます。
- 盛り上がりは山の高さで、終わりの近さは帯の右端までの距離で分かります。

#### 地と光
- 地は暗めの色にします。真っ黒ではなく、藍色の夜空のような深い紺（`#151b2d`）にします。線と字は純白ではなく、生成り（少し黄みのある白、`#f1ebdb`）にします。地と字の比は約 14.4:1、うすい字（`--muted`）でも約 8.7:1 で、WCAG の 4.5:1 を保ちます（11/7。「黒に白でコンソールのように見える」という声への直し。Gin が決めた形）。
- ボタンや枠は角を大きく丸め（18px）、枠線は細く淡く（1.5px、地との比 約 3.3:1）します。
- 書体は丸ゴシックの Zen Maru Gothic（SIL Open Font License 1.1）を Google Fonts から読みます。届くまでは今の書体で出し、待たせません（`display=swap`）。歌の途中で書体が替わらないよう、一覧を出す時に楽譜にある字の分を先に取りに行きます。Mac の Chrome では、最初の字の組が約 0.1〜0.2 秒で届きました（11/7）。
- 点滅させません。
- 派手な効果も入れません。動きは一つだけ：音が始まった瞬間、線の頭で小さな丸い光が広がって消えます（0.4 秒、一度だけ。広がりは線の太さの 2.4 倍まで、濃さは 0.6 まで。Gin、11/7）。端末で「視差効果を減らす」（動きを減らす）を選んでいるときは出しません。
- 意味を色だけに乗せず、明るさの差で描きます（これまでの決まりと同じ）。

## 4. そばの人の手順

1. ページを開くと、曲名の大きなボタンが 3〜5 個並んだ一覧が出ます。
2. 曲名を押します。
   - 線の最初の部分と、歌詞の 1 行目がすぐに出ます。
   - 「まもなく始まります」と出して、約 3 秒待ちます。
   - それから伴奏と声が鳴り始め、線が流れ始めます。
3. 途中で画面のどこかに触ると止まり、「とまっています（触ると続き）」と出ます。もう一度触ると、続きから始まります。
4. 歌い終わると「おしまい」と出ます。数秒たつと、一覧に戻ります。（Claude の案）

### そのほかの決め
- 曲が鳴っているあいだは、画面が暗くならないようにします（Screen Wake Lock API）。
  - 使えるブラウザは、作る前に MDN で確かめます。
  - 使えない端末では、画面の消える時間を延ばしてもらうよう、README に書きます。
- iPhone では、触った瞬間でないと音を鳴らし始められないことがあります。
  - そのため、曲名を押したときに音の準備をして、3 秒後に鳴らす予約をします。
- テレビに映したときに、線と歌がずれていたときだけ、そばの人が線を少し遅らせる／早める調整を一つ入れます。ずれていなければ入れません（7 章の条件 5 で確かめる）。

## 5. 楽譜データの書き方

曲ごとに一つのテキストファイルを作り、`songs/` に置きます（例：`songs/haru_no_ogawa.txt`）。伴奏のある曲は、元の本から Claude が起こします（2 章）。下の例は伴奏のない形です。伴奏の書き方は、この章の「伴奏・和音・強弱・構成」にあります。

```
# ふるさと
作詞: 高野辰之（1876–1947）
作曲: 岡野貞一（1878–1941）
出典: （典拠の URL）
拍子: 3/4
速さ: 80

[旋律]
音: F4:4 F4:4 F4:4 G4:4. A4:8 G4:4 A4:4 A4:4 Bb4:4 C5:2.
音: ……

[1番]
詞: う|さ|ぎ|追|い|し|か|の|山
読: う|さ|ぎ|お|い|し|か|の|やま
詞: ……
読: ……

[2番]
……
```

### 書き方の決まり
- **音**
  - 音名とオクターブで書きます。C4 が真ん中のドです。
  - 半音は `#` か `b` で書きます（例：`F#4`・`Bb4`）。
- **長さ**
  - `1` は全音符、`2` は 2 分、`4` は 4 分、`8` は 8 分、`16` は 16 分です。
  - 付点は、後ろに `.` を付けます。
  - 休符は `R:8` のように書きます。
  - 同じ高さをつなぐ（タイ）ときは、`F4:4~F4:8` と書きます。
- **行**
  - `音:` の 1 行が、歌詞の 1 行に当たります。
  - `[旋律]` の n 行目と、各番の n 行目の `詞:` を対にします。
  - 番ごとに旋律が違う所があれば、その番に `音:` を書いて上書きします。
    - 上書きの `音:` は、そのすぐ次の `詞:` の 1 行にだけ効きます。ほかの行は `[旋律]` のままです。（Claude の案。T1 でこの形に作った）
- **速さ**
  - `速さ:` は、4 分音符が 1 分に何回か、で書きます（例：`速さ: 80`）。拍子が 6/8 などでも同じです。（Claude の案）
- **打ちやすさ**
  - `：`（全角のコロン）と `｜`（全角の縦線）も受け付けます。
  - `//` で始まる行はメモで、読み飛ばします。
- **字と音の対応**
  - `詞:` を `|` で区切った一つ一つが、休符を除いた音一つに当たります。
  - 一つの字を二つ以上の音で伸ばして歌うときは、二つ目からの音に `ー` を当てます。
- **元・詞・字（2026-11-04 から。Gin の決定）**
  - 番の中では、歌詞の 1 行を 3 行で書きます。
    - `元:` 元の本の表記（旧かな）を、音ごとに区切ったもの。そのまま残し、README の「元の本の表記」に載せます。
    - `詞:` 今のかなを、音ごとに区切ったもの。線の上の小さな字に使います。一つの音に二字以上乗るとき（けふ→`きょう`）は、一つの区切りに書きます。
    - `字:` 画面の歌詞。漢字の後ろに（よみ）を書きます（例：`兎(うさぎ)追(お)いし　かの山(やま)`）。漢字には一つ残らずルビを付けます。全角の空白は、画面で少し間を空けます。
  - 読み込むときに、`元:` と `詞:` の数が同じか、`字:` を読みに直したものと `詞:` をつなげたもの（「ー」を除く）が同じかを確かめ、違えば行の番号を付けて知らせます。漢字にルビがないときも知らせます。
  - 漢字にするかの決め方：字を見れば意味が分かる言葉は漢字、当て字や特別な読みで字が意味の手がかりにならない言葉はかな。ただし、昔の人が祝い唄や民謡で見慣れた字（目出度く）は漢字にする（Gin）。
- **ルビ（前の書き方。`読:`）**
  - `読:` は、`詞:` と同じ数に区切ります。
  - かなの所は、`詞:` と同じ字を書きます。違う字の所だけがルビになります。
  - かなだけの行は、`読:` を省いてもかまいません。（Claude の案）
- **調**
  - 楽譜は、元の本の調のまま書きます。高さを変えたい曲だけ、頭に `移調: -2` のように半音の数を書きます。楽譜の音は元の本のまま残り、鳴らす高さ（歌の線・伴奏・MIDI）だけが動きます（ふるさとは -2 でヘ長調。Gin、2026-11-03）。移調した曲に `元の調: ト長調` のように書くと、曲の一覧の曲名の下に「元の本の高さ（ト長調）で鳴らす」の切り替えが出ます。ふだんは移調した高さで鳴らします（ふるさとだけ。春の小川は切り替えなし。Gin、2026-11-05）。
- **添え書き**
  - 頭に `添え書き: 元の詞（1912 年）` と書くと、曲の画面で、曲名のそばに小さく出します（春の小川。Gin、2026-11-04）。
- **伴奏・和音・強弱・構成**（T1 のあとで足した。2026-11-03）
  - `[旋律]` の中で、各 `音:` の行のすぐ後に、同じ小節ぶんの伴奏を `右手:` `左手:` で書きます。同じ手に別のリズムの声部があれば `右手2:` `左手2:` を足します。
  - 前奏・間奏・後奏は `[前奏]` などの見出しの下に、`右手:` `左手:` だけを書きます。
  - 前奏・間奏・後奏の中に `だんだん遅く: 70%` と書くと、その部分の頭から終わりへ、速さを元の 70% までまっすぐ落とします。`だんだん遅く: 3 小節目から 70%` と書くと、3 小節目の頭から遅くし始めます。30〜99% の範囲で書きます（ふるさとの後奏と、春の小川の最後の前奏。Gin、2026-11-03）。春の小川のように、終わりだけ遅くする前奏は、前奏を `[後奏]` に写して、そこにだけ書きます。
  - 和音は `+` でつなぎます（例：`C4+E4+G4:4`）。歌の旋律には和音を書けません。
  - 小節の区切りは `/` です。区切ると、どの小節も拍子どおりの長さかを、読み込みで確かめます。
  - 強弱は `pp p mp mf f ff` を、その音の前に一語で置きます。次の強弱まで続きます。`<` `>` は読み飛ばします。
  - `構成:` に、鳴らす順を書きます（例：`構成: 前奏 1番 前奏 2番 前奏 3番 前奏`）。D.C.・Fine は、この並びに直して書きます。
  - 伴奏の長さがその段の旋律と合わないとき、小節の長さが拍子と合わないときも、行の番号を付けて知らせます。
  - 8va.（1 オクターブ上げてひく）の所は、実際に鳴る高さで書きます。
- **耳で確かめる**
  - `node tools/score2midi.mjs songs/〜.txt 出力.mid` で、歌の旋律（フルートの音色）と伴奏（ピアノ）の MIDI を書き出します。Gin が聞いて、違う所を言います。
  - 新しく用意する曲では、終わりの伴奏の途中から速さを 70% まで落とす版も作って聞きます。しっくり来れば、その曲で採用します（楽譜を打ち込んだだけの印象をやわらげるため。Gin、2026-11-03）。遅くし始める小節は曲の速さで変えます。ふるさと（♩=80）は 3 小節目から、テンポが速めの春の小川（♩=104）は 4 小節目からにしました。
- **間違いを見つける**
  - 読み込むときに、音と字の数が合わない行は、行の番号を付けて知らせます。
  - テストでも、全部の曲のファイルを確かめます。

## 6. 歌声の録り方と、楽譜との時間のそろえ方

### 録り方
- Gin が、伴奏をヘッドホンで聞きながら主旋律を歌い、声だけを録ります（伴奏は録音に入れない）。
- 聞く伴奏は、楽譜のテキストから書き出したもの（MIDI、またはアプリと同じ音）にします。アプリが鳴らす伴奏と同じ速さなので、録った声とアプリの伴奏がそろいます。（Claude の案）
- 声のファイルは、伴奏の始まりを 0 秒にそろえて書き出します。（Claude の案）
- ファイルの形は、WAV（48 kHz・1 ch）を推します。（Claude の案）

### アプリでの鳴らし方
- 伴奏は、楽譜のテキストから、アプリの中で音を作って鳴らします（Web Audio）。音のファイルを別に用意しなくてよく、権利の心配もありません。（Claude の案）
- 声のファイルを、伴奏と同じ時刻に始めて一緒に鳴らします。

### 歌声の置き場と、ページの読み方

**決め（Gin、2026-11-03）：ア（このリポジトリの `songs/`）。**
- アプリは自由に使ってほしいが、歌をフリー素材にする必要はない（Gin）。
  - README と `songs/README.md` に「録音は MIT の対象外」と書いた。
  - 録音の扱いは「この作品の中で聴くのは自由、転載・加工は不可」と別に書いた。
- push すると履歴に残るので、人前に出せるテイクだけを入れる。

以下は、決める前に並べた案です。
大事にしたいこと：審査員が、ページを開いて曲名を押すだけで試せること。

| 案 | 置き場 | ページの読み方 | 審査員がすぐ試せるか |
|---|---|---|---|
| ア | このリポジトリの `songs/` | 同じ Pages から読む | 試せる |
| イ | 声だけを置く別のリポジトリ（例：`oto-megane-songs`）の Pages | `https://gincyagi.github.io/oto-megane-songs/` から読む。本体と同じ `gincyagi.github.io` の下なので、ページから読むのに特別な設定は要らない | 試せる |
| ウ | 置かない（使う人の端末の中） | ファイルを選んでもらう | 試せない（声のファイルが手元にないため） |

**（Claude の案）ア を主にして、ウ を添える。**
- 唱歌の声は、期間中に Gin が録るもので、声の権利は Gin にあり、旋律と詞は権利が切れています。リポジトリに置いても決まりに当たりません（運営の答え 4 は「置かなくてよい」で、置くことを止めてはいません）。
- 一つのリポジトリで完結するので、審査員が迷いません。
- 期間前に作った音（使うと決めた場合）は イ に分けます。期間中に一から作ったリポジトリに、期間前のものを混ぜないためです。
- ウ は「自分の家族の歌を見せたい」人のための入り口として残します（いまの「曲を見る」の欄。10 章の U1 とあわせて決めます）。

ア・イ に共通の決め：
- 配るときは、WAV をスマホで再生できる小さな形（AAC の `.m4a`）に変えます。
- `.wav` は、これまでどおりリポジトリに入れません。
- 置いた音は、一つ残らず README の「素材と出典」の表に載せます。
- ア のときは、リポジトリに入れてよい音を「`songs/` の中にあって、素材と出典の表に載っているもの」だけにし、Claude Code のフックで確かめます（8 章）。

### そろえ方（自動で合わせ、Gin が直す）
伴奏に合わせて録るので、声は楽譜の速さにほぼそろいます。そのため、まず楽譜どおりの時刻で線を描き、ずれが目立つときだけ次の道具を使います。（Claude の案）

1. `tools/align.mjs`（Mac の node で動かします）で、次の 3 つを読みます。
   - 声の WAV
   - 楽譜
   - いまの高さの読み取り（`js/pitch.js`）
2. 声の高さの並びと楽譜の音の並びを、時間を伸び縮みさせて一番よく重なるように合わせます（DTW）。
3. 結果として、音ごとの始まりの秒を `songs/haru_no_ogawa.times.txt` に書き出します。歌詞の 1 行が 1 行に当たります。
4. 合っていない所は、Gin が秒の数字を直接直します。
5. 確かめるための画面（`?check` を付けて開くページ）では、楽譜の線の上に、声から読んだ高さを細い点で重ねます。
   - この点は、作り手だけが見るものです。そばの人が使う画面には出しません。

スマホの側では、時間の合わせを計算しません。安い機種でも重くならないようにするためです。

  - 理由：漢字が読めない人もルビで歌えて、漢字を知りたい人には字に出会える場になるように。旧かなは、今の多くの人には読みにくいため。
