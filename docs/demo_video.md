---

iPhone の画面収録では、歌モードの伴奏の音がちゃんと録れません（下の「調べたこと」）。
そこでデモ動画は、**画面は画面収録で撮り、音は同じ楽譜から WAV に書き出して、動画の編集でつなぎます**（Gin、2026-11-05）。

## 1. 音を WAV で書き出す（`?export=1`）

1. `index.html?export=1` を開きます（例：`https://gincyagi.github.io/oto-megane/?export=1`）。Mac の Chrome で確かめました。iPhone の Safari では保存を確かめていません。
2. 一覧のいちばん上の「**書き出す WAV に仮の主旋律を入れる**」で、仮の主旋律を入れるか選びます（入れるが既定。外すと伴奏だけ）。
3. ふるさとを元の本の高さ（ト長調）で書き出すときは、「元の本の高さ（ト長調）で鳴らす」に印を付けます。
4. 書き出したい曲の下の「**音を WAV で保存**」を押します。数秒で、ブラウザの「ダウンロード」に保存されます（Mac の Chrome なら、ふだんは「ダウンロード」フォルダ）。
   - ファイル名：`故郷（ふるさと）.wav`・`故郷（ふるさと）_元の調.wav`・`春の小川.wav`。伴奏だけのときは、名前の終わりに `_伴奏のみ` が付きます。
   - 形式：48,000 Hz・16 ビット・ステレオ。
   - **頭に 1 秒の無音**があります。曲の 0 秒（前奏の最初の和音）は、ファイルの 1 秒目です。
5. 音は、鳴らすときと同じ部品（`js/uta-audio.js` の `UtaAccompaniment`）を OfflineAudioContext で動かして作ります。音色も強弱も、アプリで鳴る音と同じです。

書き出した WAV は、このリポジトリに入れません（音と録画はリポジトリの外）。

## 2. 画面と音の頭を合わせる目印（曲の時計）

`?export=1` か `?clock=1` で開くと、曲の画面の上の真ん中に**曲の時計**が出ます。

- 曲名を押してから鳴り始めるまでは「**まもなく**」。
- 曲の 0 秒で「**0 秒**」に変わり、そのあと「1 秒」「2 秒」…と進みます（字が変わるだけで、光りません）。
- 時計は、耳に音が届く時刻（出力の遅れを引いた時刻）に合わせてあります。

編集では、画面収録の「まもなく」が「0 秒」に変わったコマを、WAV の 1 秒目に合わせます。途中の「10 秒」「60 秒」などの変わり目で、ずれていないかを確かめられます。

OnePlus 6 で、曲の時計が出ること、画面収録に書き出した WAV を重ねてもずれないことを、Gin が確かめました（2026-11-06）。

曲名を押すと全画面になり、一覧に戻ると全画面を抜けます（アドレス欄が曲によって出たり消えたりして、録画で画面の位置がそろわなかったため。Gin、2026-11-06）。全画面にできない端末（iPhone の Safari など）では、いままでどおりです。

ふるさとも春の小川も、前奏のあいだは主旋律の線が出ないので、線の動きでは頭を合わせにくいです。時計を目印にしてください。

## 3. 調べたこと：iPhone の画面収録で伴奏が途切れる（2026-11-05）

- 起きたこと：iPhone の画面収録でふるさとと春の小川を続けて録ると、録れた音が最後まで雑音のように聞こえた。その場で聞く音は普通（Gin の耳）。
- 測った結果（Claude と、Gin の側の測りの両方で）：録れた音は AAC・44.1 kHz・左右同じ。約 21.3 ミリ秒ごとに途切れ、音があるのは毎回 7〜10 ミリ秒ほどで、残りはまったくの無音。音の高さは残るが、途切れの周期（約 47 Hz）の分だけ両側に山ができ、継ぎ目で全部の帯域にプツッという音が出る（周波数の絵の縦の筋）。曲名を押すたびに音の仕組みを作り直しているので、春の小川も新しい仕組みで鳴っていたが、同じ形で途切れた。
- 試したこと（Gin が iPhone で録り直して測った）：
  - `?lat=interactive`（遅れの小さい設定）：だめ。21.3 ミリ秒ごとに途切れ、標本の 55% が無音。
  - `?sr=44100`（標本化周波数を収録と同じにする）：だめ。周期も同じ。
  - 標本化周波数を変えても周期が変わらないので、区切っているのは画面収録の側と推定。21.3 ミリ秒は、48 kHz の 1024 標本にあたる。
- 確かめ用の印（既定はいまのまま：`latencyHint:'playback'`・標本化周波数は端末まかせ・Audio Session は `playback`）：
  - `?lat=interactive|balanced|playback`：AudioContext の `latencyHint`。
  - `?sr=44100` など：AudioContext の `sampleRate`（選べない値なら端末まかせにする）。
  - `?session=0`：`navigator.audioSession.type = 'playback'` を設定しない（消音のとき鳴らなくなるので、確かめるときだけ）。まだ試していない。
  - `?debug=1`：画面の下に、音の仕組みの状態・標本化周波数・遅れを出す。
- 読んだ資料（2026-11-05 に確かめた）。画面収録と Web Audio の組み合わせをそのまま書いた公式の資料や不具合の報告は見つからなかった。
  - MDN「AudioContext() constructor」：`sampleRate` を指定しなければ出力の機器が好む値。`latencyHint:'playback'` は遅れより電池を優先。https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/AudioContext
  - WebKit Bug 259899「Web Audio glitches when hardware buffer size is not divisible by 128」（2023-08 に直った）。https://bugs.webkit.org/show_bug.cgi?id=259899
  - WebKit Bug 224874「Stuttering audio from WebRTC in iOS 14.4.2」：コントロールセンターを引き出すと音が乱れる。未解決。https://bugs.webkit.org/show_bug.cgi?id=224874
- 方針：iPhone の画面収録の音は使わない。デモ動画の音は、上の 1 の WAV を使う。
